# Перевірки безпеки та QR

Після запуску локального Worker перевірити такі сценарії:

| Сценарій | Очікування |
|---|---|
| Валідний QR активного заняття, учень у групі | `201`, створено одну відмітку |
| QR з попереднього часового інтервалу | `410 QR_EXPIRED` |
| Змінений підпис | `401 INVALID_QR_SIGNATURE` |
| QR для закритого/запланованого заняття | `409 LESSON_NOT_ACTIVE` |
| Учень не є членом групи | `403 NOT_GROUP_MEMBER` |
| Повторна відмітка | `409 ALREADY_ATTENDED`, рядок не дублюється |
| Запит без сесії | `401` |
| Некоректний формат JSON/QR | `400` |
| Невірний пароль | `401`, сесія не створюється |
| Реєстрація учня або викладача | `202`, заявка створена зі станом `pending`, сесія не видається |
| Вхід до схвалення заявки | `403 ACCOUNT_PENDING` |
| Створення адміністратора з правильним кодом bootstrap | `201`, роль адміністратора активована |
| Повторне створення адміністратора через bootstrap | `409` |
| Адміністратор схвалює або відхиляє заявку | стан змінено; рішення записано разом з ID адміністратора |
| Повторна реєстрація логіна | `409` |
| Реєстрація з паролем довжиною 6 символів латиницею | `202` |
| Реєстрація з паролем коротшим за 6 символів або з кирилицею | `400` |
| Учень створює групу | `403` |
| Викладач додає схваленого учня за логіном до власної групи | `201` |
| Додавання логіна, якого немає серед схвалених учнів | `404` |
| Власник групи переглядає список відміток заняття | `200`, для кожного учня повертається стан відмітки |
| QR-відмітка після порога запізнення | запис має статус `late` і фактичні хвилини запізнення |
| Викладач вручну змінює статус відвідування | статус і автор зміни збережені, оцінка не втрачається |
| Закриття заняття | для учнів без відмітки створено статус `absent` |
| Викладач виставляє або очищає оцінку | приймається лише ціле число 1–12 або `null`; оцінка видна в історії |
| Викладач змінює оцінку чужого заняття | `404` |
| Редагування оцінки після календарного дня заняття | `409 GRADE_WINDOW_CLOSED` |
| Інший викладач переглядає список відміток чужого заняття | `404` |
| Викладач читає чужу групу | `404` |
| Прострочена cookie-сесія | `401` |
| Запит із недозволеного Origin або без CSRF | `403` |

Після сценаріїв перевірити, що тимчасові тестові облікові записи, групи, заняття, сесії та відмітки видалено.

Локальний автоматизований набір: `cd backend && npm run test:security`. Він запускає D1/Worker інтеграційний сценарій, а потім видаляє створені ним дані.
