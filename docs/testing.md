# Перевірки безпеки та QR

Після запуску локального Worker перевірити такі сценарії:

| Сценарій | Очікування |
|---|---|
| Валідний QR активного заняття, учень у групі | `201`, створено одну відмітку |
| QR з попереднього часового інтервалу | `410 QR_EXPIRED` |
| Змінений підпис | `401 INVALID_QR_SIGNATURE` |
| QR для закритого/запланованого заняття | `409 LESSON_NOT_ACTIVE` |
| Учень не є членом групи | `403 NOT_GROUP_MEMBER` |
| Повторна відмітка | `409 ALREADY_ATTENDED`, рядок не дублюється |
| Запит без сесії | `401` |
| Некоректний формат JSON/QR | `400` |
| Невірний пароль | `401`, сесія не створюється |
| Реєстрація з роллю teacher | `403`, користувач не створюється |
| Повторна реєстрація email | `409` |
| Учень створює групу | `403` |
| Викладач читає чужу групу | `404` |
| Прострочена cookie-сесія | `401` |
| Запит із недозволеного Origin або без CSRF | `403` |

Після сценаріїв перевірити, що тимчасові тестові облікові записи, групи, заняття, сесії та відмітки видалено.

Локальний автоматизований набір: `cd backend && npm run test:security`. Він запускає D1/Worker інтеграційний сценарій, а потім видаляє створені ним дані. Останній прогін пройшов успішно.
