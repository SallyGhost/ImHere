# Frontend ImHere

## Карта страниц

```text
Главная
├── Регистрация ученика
└── Вход
    ├── Панель преподавателя
    │   ├── Группы → участники
    │   ├── Занятия → создание → занятие с QR
    │   └── Статистика посещаемости
    └── Панель ученика
        ├── Мои группы
        ├── Сканирование QR → подтверждение результата
        └── История посещаемости
```

Страницы — отдельные HTML-файлы в `frontend/`. Каждая использует общие `main.css`, `components.css`, `responsive.css` и ES-модули в `frontend/js/`. Модули разделены по API, авторизации, панели, группам, занятиям, QR, посещаемости и утилитам.

## Схематичные макеты

```text
Публичная страница:   логотип                         вход | регистрация
                      заголовок и краткое описание
                      [войти] [создать аккаунт]

                      [форма: email, пароль, кнопка]
                      сообщение о результате | ссылка на соседнюю форму

Панель:               логотип     email пользователя             выход
                      заголовок страницы и краткое описание
                      [метрика] [метрика] [метрика]
                      [основной список / таблица]

QR преподавателя:     логотип     состояние занятия               выход
                      [QR и таймер] [инструкция и состояние]

Сканер ученика:       логотип     email пользователя             выход
                      [видеопоток + выбор камеры]
                      [включить / остановить] [ручной JSON токен]
                      подтверждение результата и история
```

Перед публикацией укажи origin Worker в `frontend/js/config.js`, например:

`frontend/js/config.js` уже указывает на опубликованный Worker: `https://imhere-api.ilya64misko.workers.dev`.

Это публичный URL API, не секрет. Точный frontend origin должен присутствовать в `ALLOWED_ORIGINS` Worker. Для локальной разработки API автоматически направляется на `http://localhost:8787`.

## Публикация

Репозиторий хранит сайт в `frontend/`, тогда как публикация Pages из ветки принимает только `/` или `/docs`. Для публикации из отдельного каталога добавлен `.github/workflows/deploy-pages.yml`: он загружает в Pages только `frontend/` при push в `main`.

В Settings → Pages выбери Build and deployment → Source → GitHub Actions. После push в `main` открой Actions и дождись завершения `Deploy ImHere frontend to GitHub Pages`. URL будет формата `https://sallyghost.github.io/ImHere/`. Сам workflow не меняет настройки репозитория и не может выполниться до push.

## Адаптивная проверка

Контрольные ширины: 360, 390, 768, 1366 и 1920 px. Для главной и входа проверено отсутствие горизонтального переполнения. CSS отдельно адаптирует сетки до одной колонки на мобильном, а окно камеры получает вертикальное соотношение сторон и достаточную высоту.

Камера браузера работает только на HTTPS (или localhost). Если камера запрещена или отсутствует, QR токен можно вставить вручную; сервер выполняет те же проверки подписи, времени и членства.
