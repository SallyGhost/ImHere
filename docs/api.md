# API ImHere

Усі API-відповіді мають тип `application/json`. Сесії передаються у `HttpOnly; Secure; SameSite=None; Partitioned` cookie; у D1 зберігається лише SHA-256 хеш токена. Для `POST`/`DELETE` браузер спершу отримує CSRF-токен через `/api/auth/csrf`, потім надсилає його у `X-CSRF-Token`. Worker також вимагає точний дозволений `Origin`.

## Авторизація

- `GET /api/auth/csrf` — встановлює короткоживучу CSRF-cookie і повертає CSRF-токен.
- `POST /api/auth/register` — реєструє учня; тіло `{ "email": "...", "password": "..." }`. Роль `teacher` не можна вибрати у публічній реєстрації.
- `POST /api/auth/login` — тіло `{ "email": "...", "password": "..." }`; повертає користувача та строк дії сесії, а сесію встановлює cookie.
- `GET /api/auth/me` — повертає користувача поточної сесії.
- `POST /api/auth/logout` — відкликає поточну сесію та очищає cookies.

Паролі зберігаються у форматі `pbkdf2-sha256$<iterations>$<salt-hex>$<hash-hex>` з індивідуальною 16-байтовою сіллю та окремим Worker secret `AUTH_PEPPER`. Worker створює лише учнівські акаунти; акаунти викладачів створюються довіреним адміністративним процесом.

## Групи викладача

- `GET /api/groups` — список власних груп викладача; для учня повертає лише групи, до яких його додано.
- `POST /api/groups` — створення групи; тіло `{ "name": "..." }`.
- `GET /api/groups/:groupId` — інформація про власну групу.
- `GET /api/groups/:groupId/members` — склад групи.
- `POST /api/groups/:groupId/members` — додавання учня; тіло `{ "studentId": "..." }`.
- `DELETE /api/groups/:groupId/members/:studentId` — видалення учня.

Додавати до групи можна лише користувача з роллю `student`. Викладач не може читати чи змінювати чужу групу.

Список груп учня містить `id`, `name`, `teacher_id`, `created_at`, `joined_at` та кількість учасників; персональні дані інших учнів не повертаються.

## Заняття викладача

- `GET /api/lessons` — список власних занять; необов'язковий `?groupId=...` фільтрує за власною групою.
- `POST /api/lessons` — створення запланованого заняття; тіло `{ "groupId": "...", "title": "..." }`.
- `GET /api/lessons/:lessonId` — інформація про власне заняття.
- `POST /api/lessons/:lessonId/start` — перехід `planned` → `active` із часом початку.
- `POST /api/lessons/:lessonId/close` — перехід `active` → `closed` із часом завершення.

Завершене заняття не можна запустити повторно.

## Динамічний QR та відвідування

- `GET /api/qr/lessons/:lessonId/token` — викладач отримує HMAC-SHA-256 підписаний токен тільки для власного активного заняття.
- `POST /api/attendance/qr` — учень надсилає `{ "token": { "version": 1, "lessonId": "...", "timeSlot": 123, "signature": "..." } }`.

Токен діє лише у поточному 25-секундному інтервалі за часом Worker. Перевірка також вимагає активного заняття та членства учня у його групі. Унікальність D1 відхиляє повторну відмітку з кодом `ALREADY_ATTENDED`. Закриття заняття негайно блокує токени, що ще не встигли протермінуватися.

## Перевірка запитів та помилки

JSON-тела обмежені 16 KiB та перевіряються на коректний формат, обов'язкові поля, типи й довжину. ID групи, учня та заняття перевіряються на існування та належність перед записом. SQL-значення передаються тільки через D1 `.bind(...)`. D1 зберігає атомарні лічильники частоти, а щоденний Cron видаляє прострочені сесії та старі лічильники.

Помилки повертаються у JSON зі статусами `400`, `401`, `403`, `404`, `409`, `410`, `413`, `415`, `429` або `500`. Відмова повторного відвідування має структурований код `ALREADY_ATTENDED`.

Для браузерного розгортання встанови `ALLOWED_ORIGINS` точним origin frontend. У конфігурації вже є `https://sallyghost.github.io` та локальні origin для розробки. Для GitHub Pages і `workers.dev` cookies є міжсайтовими; `Partitioned` допомагає у браузерах із CHIPS, але підтримку треба перевірити на цільових браузерах. API URL для frontend передається через `window.IMHERE_API_BASE_URL`.

Модуль `frontend/js/qr-scanner.js` відкриває обрану камеру браузерною бібліотекою ZXing Browser 0.2.1; камера вимагає HTTPS, окрім localhost у розробці. Ручне вставлення токена також передає його на сервер для перевірки. `frontend/js/qr.js` рендерить токен через qrcode.js і отримує новий у кожному часовому інтервалі.

Frontend складається з окремих сторінок у `frontend/` та модулів `api.js`, `auth.js`, `dashboard.js`, `groups.js`, `lessons.js`, `qr.js`, `qr-scanner.js`, `attendance.js` і `utils.js`. Перед публікацією задай `window.IMHERE_API_BASE_URL` у `frontend/js/config.js` та додай точний Pages origin до `ALLOWED_ORIGINS` Worker.
